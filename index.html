The Problem

People struggle to complete official forms (at government offices, hospitals, banks, and schools) due to dense bureaucratic terminology, language barriers, unclear requirements, missing document surprises, and stressful reliance on third-party help.

The Goal

Make form completion simple, guided, accessible, predictable, and confidence-building — transforming an intimidating task into step-by-step progress.

Core Flow
Scan→ Understand→ Complete→ Check Documents→ Review→ Submit
Key Features (USP)
  • Field-by-Field Explanations (Core USP): Breaks down complex labels (like "Gross Annual Income") into plain language before entry.
  • Form Scanning: Instant OCR camera framing to recognize physical paper forms.
  • Bilingual Guidance: Quick Tamil / English toggle for non-native English speakers.
  • Voice Guide & Progress Bar: Audio playback option and predictable step counters.
  • Document Checklist & Review: Pre-submission validation to prevent office rejection.
Accessibility Highlights

Cognitive step chunking, WCAG AAA text contrast, 48px touch targets, bilingual audio assistance, and persistent progress tracking.

Prototype Mechanics

Built in Figma using On Click, After Delay (1500ms Splash Dissolve), Navigate To, and Smart Animate (300ms ease-out) to mimic real native mobile feel.

The Problem

Homeowners and tenants struggle to find and compare reliable local service professionals (plumbers, electricians, cleaners, appliance technicians). Key frictions include hidden pricing, uncertain arrival times, and zero tracking after making a phone call.

Core Flow
Discover→ Compare→ Select→ Book→ Confirm→ Track→ Review
Information Priority Architecture

To eliminate booking friction, cards are organized strictly by trust signals: Provider → Rating → Service → Distance → Availability → Pricing → Booking CTA.

Information Architecture (IA)

Primary Nav: Home, Services, How It Works, About, Login, Sign Up.
Core Modules: Service Category • Provider Listing • Provider Profile • Booking • Booking Confirmation • Live Tracking • Rating & Review.

Limitations — Stated Honestly

FixNear is a design concept and interactive Figma prototype, not a production application. There is no real backend database, GPS tracking pipeline, payment gateway, authentication server, or live booking engine. All provider names, ratings, pricing, and home screen customer quotes are design placeholders used solely to test and demonstrate the user experience.

Future Integrations (Concept Only): Real-time provider availability feeds, actual GPS geolocation API, backend authentication, secure payments, verified user reviews, booking history, and push notifications.

// Lightweight, zero-dependency accessible tab controller
function initTabs(tabListSelector) {
  const tabs = document.querySelectorAll(`${tabListSelector} [role="tab"]`);
  
  tabs.forEach(tab => {
    tab.addEventListener('click', (e) => {
      const targetPanelId = tab.getAttribute('aria-controls');
      
      // Update tab selection states
      tabs.forEach(t => {
        t.setAttribute('aria-selected', t === tab ? 'true' : 'false');
        t.tabIndex = t === tab ? 0 : -1;
      });

      // Show targeted panel
      document.querySelectorAll('[role="tabpanel"]').forEach(panel => {
        panel.hidden = panel.id !== targetPanelId;
      });
    });
  });
}
UX Principles

What I check for before calling a screen done.

Four pragmatic heuristics that govern every layout, button placement, and microcopy decision.

01

Clarity over cleverness

If a user has to pause and decode an unfamiliar icon or ambiguous label, the interface has failed. Explicit text and conventional interactions build immediate trust.

02

Consistency builds trust

Components must behave identically across every screen they appear on. Predictable colors, padding, and font scales allow users to focus on their task, not the interface.

03

Feedback for every action

Users should never be left wondering if an input registered. Clear visual state changes, progress meters, and confirmation screens confirm that the system is listening.

04

Accessible by default

Contrast ratios, large touch targets, logical document heading order, and screen-reader semantics are structural requirements built into the earliest wireframes, not retrofitted afterthoughts.
